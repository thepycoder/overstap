# First end-to-end run — 2026-10-29

MOTIS v2.11.4 (static binary from `ghcr.io/motis-project/motis:latest`) on a
2-vCPU / 8 GB cloud box. Inputs: NMBS + De Lijn GTFS (14 days), NMBS + De Lijn
GTFS-RT, five GBFS feeds, Belgium OSM (openstreetmap.fr, cleaned).

## Import & serving

| Step | Time |
|---|---|
| osr (street graph) | 35 s |
| adr (geocoding) | 1 min 45 s |
| tt (NMBS + De Lijn, 14 days) | 18 s |
| footpaths + matching | 10 s |
| **Total** | **2 min 51 s**, 1.4 GB `data/` |

Server RAM ≈ 1.2 GB. RT update ≈ 0.9 s per minute; trip-match rate 95 % (NMBS),
99 % (De Lijn). Tiles (map background) disabled to save time; enable for the UI.

## Use case 1 — Lokeren → Nekkerhal (Fri 08:00)

Destination must be the entrance (Nekkerspoel-Borcht 19, 51.02566,4.50349). The
building centroid snaps to a street on the far side and inflates last-mile
walks by ~8 min. Geocoding venue → entrance is a TODO.

| Last mile | Arrive | Notes |
|---|---|---|
| Folding bike | **08:55** | S34 → Dendermonde → IC → Mechelen, bike 9′ |
| Blue-bike round trip from Mechelen station | **08:56** | 53 bikes; ride back ≈9′ later |
| Donkey Republic, parked at hub (overstap) | 08:58 | Hub "Sportpark De Nekker", 2′ walk |
| Donkey Republic as MOTIS planned it | 08:57 | **Wrong**: drops the bike at the door |
| Walk + bus | 09:17 | |

Findings:
- Donkey's GBFS has no geofencing zones and no `return_constraint`, so MOTIS treats
  it as free-floating. overstap corrects this (`lastmile::fix_hub_only`).
- Blue-bike is `ROUNDTRIP_STATION`, so MOTIS never offers it for a one-way last
  mile. overstap prices it as a tour from every alighting point (`lastmile::tour_option`).
- This reproduces the real-life conclusion: Blue-bike from Mechelen beats Donkey.

## Gaps found

1. Donkey (and probably other hub-based operators) mis-modelled in GBFS → hand-kept provider rules.
2. `minTransferTime` can only *raise* transfer times; NMBS GTFS uses 240 s (300 s at some
   stations). Tighter transfers need preprocessing `transfers.txt`.
3. Venue geocodes snap badly; prefer entrances / addresses.
4. Openstreetmap.fr extract crashes osr (missing nodes) → `tools/fix_osm_refs.py`.

## Ad-hoc query — Retie ('t Veld → Veldenstraat) → Lokeren Hillarestraat, 19:45

"'t Veld" is not in OSM, Nominatim or De Lijn's stops; Veldenstraat (Retie centre) was used.

| Mode | Leave | Arrive | Route |
|---|---|---|---|
| Folding bike | 19:52 | **22:21** | bike 42′ to Mol, S33 20:34 → Berchem, IC 21:42 → Lokeren 22:09, bike 12′ |
| Bus + train + Donkey | 20:24 | 22:58 | bus 47 → Mol, IC 21:03 → Berchem, S34 22:01 → Lokeren 22:40, Donkey 13′ to hub at Roggestraat |
| Bus + train + walk | 20:24 | 23:21 | same trains, walk 41′ (2.9 km) |
| Next bus, walk | 21:24 | 00:21 | last working connection |

Findings:
- MOTIS caps walking before/after transit at 15 min by default, so a 2.9 km walk from
  Lokeren station became "wait for the 05:34 bus". `--carry foot` now allows 60 min.
- `--max-bike` (default 30) added; Retie → Mol by bike is 42 min.
